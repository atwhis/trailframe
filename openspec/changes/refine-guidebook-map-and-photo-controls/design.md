## Context

Trailframe 当前由 Mapbox Static Images API 返回底图，再由 Sharp/SVG 合成轨迹、统计和海拔曲线。Guidebook 默认使用 `mapbox/satellite-streets-v12`，但服务端还会通过 Overpass 搜索轨迹周边 5 公里山峰，并额外绘制山峰图标、文字卡片和引导线。轨迹分析已经产生按本地日期排序的 `dailySections`，但 Guidebook 渲染器刻意忽略它并绘制单色路线。

照片编辑器已经用归一化坐标保存两个图层的位置、缩放和旋转，并单独保存透明度，但界面主要暴露无数值滑块；统计图层虽有旋转状态，渲染与控件尚未使用。参见 proposal.md 和两份 capability delta spec 的行为要求。

## Goals / Non-Goals

**Goals:**

- 继续使用现有 Mapbox Static Images 服务端合成边界，不在浏览器暴露 token。
- 用一个可由 Static Images API 渲染的 Mapbox Studio 样式完成影像、道路名称与纯文字山峰标签的组合。
- 删除 Overpass 依赖和服务端独立山峰绘制路径，使地图只存在一套山峰标签。
- 复用现有 `dailySections`，让两个模板都稳定地按日期映射颜色。
- 让照片海报两个图层共享相同的数值模型、单位和控件行为，同时保持图层独立。

**Non-Goals:**

- 不接入 OpenTopoMap 栅格瓦片或新的 OSM 瓦片供应商。
- 不显示等高线，不从 DEM 补全山峰海拔，也不保证每个可见山峰都被地图标签引擎选中。
- 不恢复周边最高峰排名、5 公里半径筛选、山峰数量统计或独立山峰卡片。
- 不给 Guidebook 增加日期颜色图例、分日行程列表或关键节点列表。
- 不增加照片画布比例、输出尺寸预设、图层联动开关或项目持久化。

## Decisions

### 使用 Mapbox Studio 自定义经典样式承载 OSM 衍生标签

以当前卫星街道经典样式为起点创建自定义 Guidebook 样式，保留卫星影像，使用 Mapbox Streets 矢量数据中的道路与自然地物名称。道路和大部分自然地物标签来自 OSM 更新源，山峰标签可以使用名称与 `elevation_m`；最终样式通过 `MAPBOX_GUIDEBOOK_STYLE=<username>/<style-id>` 配置。

样式只保留必要的道路名称和山峰文字层，隐藏重复道路、普通 POI、无关地点标签及所有等高线层。山峰文本优先使用本地名称或简体中文名称回退，并在 `elevation_m` 存在时以第二行显示“{value} m”；没有海拔时只显示名称。山峰层不绑定 sprite 图标，因此不会出现三角形、山形或其他图标。

选择该方式而不是叠加 OpenTopoMap 栅格瓦片，是因为 OpenTopoMap 的等高线和文字已烘焙在同一张图片中，无法只移除等高线。也不在 Static Images 请求中临时拼装多层外部矢量源：Mapbox Static Images 对新增数据源有访问限制，而托管的 Studio 样式能在现有单次底图请求中稳定完成标签碰撞和署名。

Mapbox Standard/Standard Satellite 当前不属于本设计依赖；继续使用经典或自定义 Studio 样式，避免 Static Images 兼容性差异。若自定义 Guidebook 样式不可访问，回退到 `mapbox/satellite-streets-v12` 并返回样式降级警告，而不是回退到包含等高线的 Outdoors。

### 删除独立山峰查询而不是保留隐藏开关

从地形海报生成链路移除 Overpass 请求、半径计算、山峰排序、标签避让和峰数响应信息。API 配置只报告地图服务是否可用；海报结果不再包含 `peakCount`，CORS 不再暴露对应响应头。

不保留 feature flag 或备用 Overpass 路径，因为新需求明确要求取消搜索。保留隐藏分支会继续增加超时、测试、文档和署名负担，也可能在配置错误时重新产生重复山峰标签。

Modern 模板仍可使用其配置的 Mapbox 样式，但同样不执行独立山峰查询。无 token 的演示底图和页面占位视觉也去掉等高线语言，改用抽象地表明暗或卫星质感渐变，避免与最终样式约定冲突。

### 由日期区段统一驱动两个模板的路线颜色

路线渲染先确定绘制区段：存在 `dailySections` 时两个模板都使用这些区段；否则使用原始 `segments` 作为一个回退区段。同一日期下的多个几何段共享颜色，日期顺序沿用轨迹分析产生的排序。

颜色函数使用一组针对卫星影像优化的高对比固定色作为前若干日期，并在超出固定色数量时按确定性等距色相生成后续颜色，禁止通过取模重复使用已经分配给其他日期的颜色。Guidebook 保留浅色 halo 以提高复杂影像上的可读性；Modern 保留现有日期图例，Guidebook 不增加图例。

选择复用 `dailySections` 而不是在海报 API 重新解析时间，是为了保持浏览器轨迹摘要、共享统计与最终海报对日期边界的一致解释。没有有效时间的轨迹不会推断日期，使用单一默认强调色。

### Guidebook 默认值在 Web 和 API 同时切换

前端初始模板和请求 schema 的缺省值都改为 `guidebook`，保证页面用户与未传模板的 API 调用得到相同结果。显式传入 `modern` 的现有调用继续有效。

这是可见的默认行为变化，因此 README、API 测试和前端测试必须同步。回滚时只需恢复两个默认值，不涉及数据迁移。

### 用统一 LayerState 和数值控件表示照片图层变换

将透明度纳入两个图层共有的变换状态，使每个图层都以 `{x, y, scale, rotation, opacity, visible, locked}` 作为规范状态。内部继续保存归一化数值：位置和透明度为 0..1，缩放为倍率，旋转为角度；UI 只负责转换为百分比或度数。

建立可复用的数值范围控件，将 range 和 number 输入绑定到同一个规范值，并为单位、步长、最小值、最大值和格式化提供明确参数。两个图层以相同顺序显示：X、Y、整体缩放、旋转、透明度。数字输入在失焦或确认时解析并钳制；空值或非数字恢复最后一个有效值。拖动画布回写 X/Y 后，数字输入立即同步。

共同参数采用同一单位和范围，方便输入相同数值，但不会自动联动两个图层。轨迹颜色、线宽、描边和阴影仍是轨迹专属；指标、字号、布局、对齐、背景和阴影仍是统计专属。统计组在 Konva 渲染时应用旋转和整体透明度，使文字、背景与阴影保持一起变换。

### 固定画布尺寸只展示、不新增尺寸状态

预览仍使用 600×900 的逻辑 Stage，导出继续通过 `pixelRatio` 生成 1600×2400 图片。界面把“输出尺寸 1600×2400 px”作为明确只读信息展示，不为尺寸创建新的可编辑状态，避免在本变更中引入照片裁剪、九宫格和布局重算问题。

## Risks / Trade-offs

- [Mapbox Studio 样式属于项目外部配置，Git clone 后无法仅靠代码重现] → 在仓库记录克隆基础样式、保留/隐藏层、山峰文字表达式、署名和环境变量格式，并为不可访问样式提供卫星街道降级。
- [地图标签碰撞可能隐藏部分道路或山峰] → 通过样式中的 zoom、rank、文字大小和碰撞设置控制密度；接受地图标签不等同于周边最高峰清单。
- [部分 OSM 山峰缺少海拔] → 只显示名称，不从轨迹高程或 DEM 猜测海拔。
- [卫星背景导致日期颜色局部对比不足] → 使用固定亮色调色板和浅色 halo，并通过样例 GPX/KML 做视觉验收。
- [轨迹跨越很多日期时颜色辨识下降] → 禁止颜色取模复用，并以确定性色相继续生成；Guidebook 仍不增加图例以遵守版式约束。
- [删除 API 配置字段和响应头影响已有调用方] → README 标注迁移，测试显式确认字段消失；本 demo 没有持久化客户端状态。
- [数字输入的四舍五入可能与内部浮点值产生轻微跳动] → 规范状态保留浮点精度，UI 仅按单位显示整数或有限小数，提交时统一解析和钳制。

## Migration Plan

1. 在 Mapbox Studio 克隆兼容 Static Images API 的卫星街道经典样式，按设计保留道路名与纯文字山峰名称/海拔，隐藏等高线、山峰图标和重复标签。
2. 先在开发环境配置新的 `MAPBOX_GUIDEBOOK_STYLE` 并用项目 GPX/KML 检查地图密度、中文回退、海拔文本和署名。
3. 删除 Overpass 与独立山峰绘制链路，同时更新无 token 演示底图、API 契约、页面文案和测试。
4. 切换 Guidebook 默认值并启用两个模板的按日颜色映射，验证同日同色、跨日异色和无时间单色。
5. 引入共享数值控件和统一图层状态，验证拖动、数字输入、滑块、预览和高分辨率导出一致。
6. 更新 README 与环境变量示例，运行单元测试、集成测试、类型检查、生产构建和浏览器视觉冒烟测试。

回滚可以恢复前一版本代码和原 `MAPBOX_GUIDEBOOK_STYLE`；没有数据库或用户项目数据需要迁移。
