## Context

本 change 从空项目开始，需求跨浏览器 UI、轨迹分析、服务端第三方地图调用和图片合成。用户样例 KML 由多个 `gx:Track` 组成，样例 GPX 含轨迹、时间、海拔及航点；累计升降必须消除设备海拔抖动。首版实现已经提供 Modern 地形海报和照片海报编辑器，但地形海报仍是通用深色信息面板，山峰主要表现为文字标签，照片统计则由单个同字号文本节点绘制。新增需求要在保持现有行为兼容的同时加入以真实地貌为主体的 Guidebook 模板，并改善照片统计的视觉层级和透明度控制。行为边界见三个 capability spec。

## Goals / Non-Goals

**Goals:**

- 用单一 npm workspace 提供可本地运行、自动测试、生产构建和 GitHub 托管的代码库。
- 让轨迹解析与分析成为前后端共享、无状态、可单元测试的纯 TypeScript 模块。
- 将照片像素限制在浏览器中，将地图服务凭据和远端请求限制在 API 中。
- 即使没有 Mapbox token 或 Overpass 不可用，也能生成明确标识的可下载 demo 海报。
- 保留 Modern 模板，并用可独立选择的 Guidebook 模板提供卫星地表或地形起伏更明显的海报。
- 让 Guidebook 在没有日期、分日区段或航点时仍能以单色轨迹、山峰和基础统计生成完整结果。
- 让照片统计信息以独立指标块呈现，但继续作为一个整体图层编辑和导出。

**Non-Goals:**

- 不处理 HEIC、GIF、视频、Live Photo 或动态海报。
- 不做账号、云端照片存储、项目持久化和多人协作。
- 不用 DEM 补全缺失海拔，也不提供专业测绘精度保证。
- demo 不逐个拖动统计指标；所选指标作为一个统计组编辑。
- 不用大模型生成或改写地图地貌、山峰、轨迹、统计数字和文字。
- Guidebook 不生成分日行程、关键节点列表或路线图例，也不从缺失数据中推断这些内容。

## Decisions

### npm workspace 与责任分层

代码采用 `apps/web`（React/Vite）、`apps/api`（Fastify/Sharp）和 `packages/track-core`（解析、分析、投影、共享类型）。这比两个独立仓库更容易共享 `TrackData` 类型与测试样例，也便于单次 GitHub clone 后启动。替代方案是全前端应用，但会暴露地图 token 且无法稳定控制远端请求。

### 浏览器解析并复用统一 TrackData

文件在浏览器中解析为带显式 `segments` 的 `TrackData`，随后同一对象用于两类海报；请求地形海报时只上传轨迹数据，不上传原文件。XML 解析器兼容浏览器并保留 GPX/KML 的轨迹段、时间、海拔和航点。多日颜色按时间戳格式中的时区换算后的本地日历日分组，而不是按几何段分组。

距离按每段相邻点 Haversine 累加，绝不跨段连接。海拔先线性插补短缺口，再使用距离窗口平滑，之后采用 3 米迟滞阈值累计趋势反转，减少 GPS 噪声；样例结果用范围断言防止算法漂移。替代方案是直接累计逐点差值，会显著高估爬升。

### 服务端合成地形海报

API 计算适配轨迹范围的 Web Mercator 相机，从 Mapbox Outdoors Static Images API 获取仅含底图的位图，再由 SVG/Sharp 绘制简化后的轨迹、山峰、曲线、图例和统计。轨迹不放进 Mapbox URL，避免长轨迹超过 URL 长度限制。`MAPBOX_ACCESS_TOKEN` 仅在服务端环境变量中读取。

没有 token 时生成带等高线视觉语言和“演示底图”标识的确定性 SVG 占位图；Mapbox 或 Overpass 失败也分别降级，不阻断最终 PNG。这使 CI 不依赖外网，同时让用户在添加 token 前就能验证浏览器→API→海报的完整链路。

### Modern 与 Guidebook 模板选择

地形海报请求增加 `template: "modern" | "guidebook"`，未传值时默认为 `modern`，避免破坏现有调用。Web 在生成前提供模板选择，并将模板值发送给 API。Modern 继续使用现有 Outdoors 底图、分日颜色和深色统计布局。

Guidebook 使用单独的服务端地图样式配置 `MAPBOX_GUIDEBOOK_STYLE`，默认选择 Mapbox 卫星街道样式；生产环境可以把它指向组合卫星影像、hillshade 和等高线的自定义 Mapbox Studio 样式。样式值与 token 一样不返回浏览器。相比在后端自行合成 DEM，该方案复用 Static Images 接口，能以较小改动获得真实地表纹理，并保留未来替换地图提供者的边界。

Guidebook 采用“标题与路线概要 → 大面积地貌地图 → 基础统计 → 海拔曲线”的纵向结构。轨迹跨多个日期时仍合并为单一强调色绘制，不生成左右侧栏、分日列表、关键节点列表或路线图例。卫星背景上仅使用局部渐变、文字描边或小范围半透明底色增强可读性，避免用大面积不透明面板覆盖地貌。

地图样式请求失败时优先回退到已有地图样式并返回警告；没有 token 时继续使用确定性占位底图，同时明确标记并非真实地貌。所有路线、山峰、文字和统计仍由 SVG/Sharp 确定性绘制，不引入大模型渲染步骤。

### 周边高峰查询与筛选

API 用轨迹外包框加 5 公里余量请求 Overpass 的 `natural=peak`，只接受有效 `name` 与数值 `ele`。随后计算每座峰到简化轨迹点的近似最小距离，过滤 5 公里外结果，并按“较高优先、距离为次”选择最多 5 座。请求设置短超时；失败返回警告并继续合成。

Modern 保留现有山峰标签。Guidebook 将峰顶坐标投影到地图画布，绘制小型峰顶标记、名称和海拔，必要时用细引导线连接。每个标签在峰顶周围的若干候选方向中选择位置，并避让海报边缘、已有山峰标签和主要轨迹线；当无法完全避让时优先保留名称与海拔，减少标签底色面积。该方法不会生成山体图形，山体视觉由底图中的卫星地表、hillshade 或等高线提供。

### React-Konva 照片编辑器

照片通过对象 URL 直接进入 Konva 画布，永不进入 API。轨迹层与统计组分别持有 `{x, y, scale, rotation, visible, locked}`，其中位置使用 0..1 归一化坐标；预览渲染时映射到画布像素，导出时提高 `pixelRatio`，因此布局不会漂移。九宫格只是写入预设归一化坐标，自由拖动仍更新同一模型。

轨迹使用基于经纬度归一化的局部平面路径，并提供颜色、线宽、透明度、阴影和描边。统计组从单个拼接文本节点调整为一个 `StatisticsGroup`，其下按用户选择创建多个 `MetricBlock`；每个指标块分别绘制大号数值与单位，以及下一行的小号指标名称。横向布局排列指标块，纵向布局堆叠指标块，但它们不拥有独立拖动状态。

统计组在既有位置、缩放、旋转、显示和锁定状态之外增加归一化 `opacity: 0..1`，UI 以 0%–100% 滑块编辑。透明度设置在整个统计组上，因此数值、名称、背景和阴影一起变化，而轨迹继续使用独立透明度。预览和高分辨率导出复用同一节点树与状态，确保层级排版和透明度一致。导出通过 canvas 重新编码 PNG/JPEG，自然移除原照片 EXIF。

## Risks / Trade-offs

- [Mapbox Static API 额度、样式或许可发生变化] → 封装地图提供者、保留署名、提供无 token 占位底图并在 README 记录配置方式。
- [公共 Overpass 限流或超时] → 短超时、输入范围限制、结果数量限制和无峰降级；生产环境可替换为自建或缓存服务。
- [浏览器处理超大轨迹或照片造成卡顿] → 限制文件大小与点数、显示处理状态、绘制前 Douglas-Peucker 简化但统计仍基于原始点。
- [不同设备海拔噪声导致升降统计与运动平台不完全一致] → 固定并测试平滑/迟滞参数，在 UI 和文档中说明估算口径。
- [Web 字体或浏览器 canvas 差异] → API 的最终地形海报由 Sharp/SVG 确定性输出；照片海报使用系统无衬线字体栈并以实际导出预览验收。
- [卫星影像在不同地区明暗和色彩差异较大] → Guidebook 使用局部描边、阴影和轻量渐变提高文字及轨迹对比度，不用整块深色面板覆盖地图。
- [自定义 Guidebook 地图样式缺失或无访问权限] → 默认使用可访问的卫星街道样式，请求失败时回退到已有地图样式并返回可见警告。
- [多个山峰标签或轨迹在小范围内重叠] → 限制为至多 5 座，使用候选位置避让、引导线和紧凑标签，并优先保留名称与海拔。

## Migration Plan

1. 创建 workspace、共享模块、Web 与 API，并提交 `.env.example` 而非真实 token。
2. 用项目样例验证两种格式和统计范围；用 mock 地图/高峰响应验证 API。
3. 运行 lint/typecheck、单元/集成测试和生产构建，再执行浏览器端上传、编辑、生成与下载冒烟测试。
4. 初始化 Git 仓库，先检查 GitHub 远端历史；空仓库直接推送，非空仓库只做非破坏性整合且绝不 force push。
5. 在兼容现有 Modern 默认值的前提下加入模板请求字段、Guidebook 地图样式配置和新布局；没有新增配置时旧调用行为保持不变。
6. 用样例 GPX/KML 验证 Guidebook 的真实地貌、单色轨迹和山峰位置，并用静态照片验证统计层级、透明度及高分辨率导出。

回滚可恢复到前一 Git commit；外部服务集成可通过移除 token 回到占位底图模式。
